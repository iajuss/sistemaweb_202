**Goal:** Dashboard com composição da carteira (estado, porte, CNAE, situação cadastral, tempo de abertura), com busca e filtros.

**Depende de:** plano `2026-07-25-onboarding.md` — já mergeado neste branch: `GET /api/empresas` retorna dados reais via `listarEmpresas()`, e a Task 4 do Onboarding já corrigiu a derivação de ano a partir da data ISO em `Analysis` (`anoAbertura`, `app/home-client.tsx:131`) como efeito colateral necessário de compilação.

## Decisão: agregação no cliente, não no banco

A spec original previa `GET /api/empresas/resumo` com `GROUP BY` no Postgres. Na prática, o componente `Analysis` em `app/home-client.tsx` já implementa toda a agregação (contagem por estado/porte/CNAE/situação, faixas de tempo de abertura, busca e filtros) inteiramente no cliente, a partir do array `companies` completo — e isso já atende a todos os itens pedidos pelo cliente. Criar um endpoint de agregação server-side seria trabalho extra sem necessidade real (carteiras de um único escritório são dezenas/centenas de empresas, não milhões). Decisão: manter a agregação no cliente.

## O que já foi feito (Task 4 do Onboarding) e o que falta

Já feito: `anoAbertura(c)` deriva corretamente o ano a partir de `Empresa.abertura: string | null` (data ISO), tratando `null` defensivamente (empresa fica fora de todas as faixas, não quebra a soma/comparação).

**Falta:** as 4 faixas de "tempo de abertura" (`app/home-client.tsx:132`) ainda comparam contra anos **fixos** (`2023`, `2018`, `2011`) — corretos hoje (o "ano de referência" implícito é 2026), mas vão ficar errados conforme o tempo passa. Esta é a única coisa que resta fazer neste plano.

- [ ] **Step 1: Trocar os limiares fixos por offsets do ano atual**

Hoje: `a >= 2023`, `a >= 2018 && a < 2023`, `a >= 2011 && a < 2018`, `a < 2011` (assumindo implicitamente "agora" = 2026).

Trocar para, calculando `const anoAtual = new Date().getFullYear();` uma vez no topo da função `Analysis`:
- `"até 3 anos"`: `a >= anoAtual - 3`
- `"4 a 8 anos"`: `a >= anoAtual - 8 && a < anoAtual - 3`

- `"mais de 15"`: `a < anoAtual - 15`

Manter o tratamento de `a !== null` já existente (`anoAbertura` retorna `null` para `abertura: null`, e essas empresas devem continuar fora de todas as faixas).
